这个主题是今天的重头戏，多篇文章从不同角度探讨了如何更聪明、更有效地使用AI，以及当前AI投资模式的可持续性问题。

1. 慢即是快：用AI写出更好的代码 这篇文章挑战了“AI加速一切”的迷思。作者认为，虽然AI能快速生成大量代码，但开发者需要投入更多时间进行审查、测试和重构，最终代码质量更高，但整体开发速度可能更慢。它提醒我们，AI是工具，不是捷径，值得所有开发者深思。

  • 原文链接： Using AI to write better code more slowly
  • 讨论链接： Hacker News

2. 用“无聊”的语言与LLM合作 这篇文章建议，在与LLM合作时，使用语法简单、逻辑清晰、社区成熟的“无聊”语言（如Python、Go），而不是复杂、抽象或小众的语言。原因是LLM在这些语言上的训练数据更充分，更容易生成正确、可维护的代码。这提供了一个非常实用的工程视角。

  • 原文链接： Use boring languages with LLMs
  • 讨论链接： Hacker News
