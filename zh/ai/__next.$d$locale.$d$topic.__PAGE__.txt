#### **1. AI评估与基准测试的挑战**
这一组文章聚焦于如何准确、公正地评估AI模型的能力，揭示了当前主流基准测试存在的缺陷和新的评估方法。
*   **文章1: Exploiting the most prominent AI agent benchmarks**
    *   **说明**：来自加州大学伯克利分校的研究文章，深入剖析了当前主流AI智能体基准测试（如SWE-bench, HumanEval）中存在的根本性缺陷。文章指出，这些测试容易被“利用”（例如通过数据污染、特定提示工程获得高分），而非真正衡量模型的通用能力，对构建可信的AI评估体系提出了严峻挑战。**这篇文章是今日讨论的核心，引发了关于AI评估科学性的深度思考。**
    *   **原文链接**: https://rdi.berkeley.edu/blog/trustworthy-benchmarks-cont/
    *   **讨论链接**: https://news.ycombinator.com/item?id=47733217
*   **文章10: N-Day-Bench – Can LLMs find real vulnerabilities in real codebases?**
    *   **说明**：介绍了一个名为N-Day-Bench的新型基准测试，旨在评估大语言模型在真实代码库中发现已知安全漏洞的能力。其最大特点是每月从GitHub安全公告中更新测试用例，以防止数据泄露到模型训练集导致测试失效（即避免模型“死记硬背”）。这是对传统静态漏洞发现基准的一次重要改进尝试。
    *   **原文链接**: https://ndaybench.winfunc.com
    *   **讨论链接**: https://news.ycombinator.com/item?id=47758347

c:T651,N-Day-Bench tests whether frontier LLMs can find known security vulnerabilities in real repository code. Each month it pulls fresh cases from GitHub security advisories, checks out the repo at the last commit before the patch, and gives models a sandboxed bash shell to explore the codebase.<p>Static vulnerability discovery benchmarks become outdated quickly. Cases leak into training data, and scores start measuring memorization. The monthly refresh keeps the test set ahead of contamination — or at least makes the contamination window honest.<p>Each case runs three agents: a Curator reads the advisory and builds an answer key, a Finder (the model under test) gets 24 shell steps to explore the code and write a structured report, and a Judge scores the blinded submission. The Finder never sees the patch. It starts from sink hints and must trace the bug through actual code.<p>Only repos with 10k+ stars qualify. A diversity pass prevents any single repo from dominating the set.
