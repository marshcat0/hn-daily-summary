一、AI 时代的设计与产品思维

这一类文章聚焦 AI 对设计流程、产品决策和协作方式的深层影响。

1. Five eras of UX design and the lessons to keep in the AI era

为什么值得关注：回顾 UX 设计从贝尔实验室至今的五个时代，指出最古老的经验恰恰是 AI 时代最需要保留的。对理解 UX 学科演进脉络极有价值。

  • 原文：https://uxdesign.cc/five-eras-of-ux-design-and-the-lessons-to-keep-in-the-ai-era-d76a548747a9

2. The most important product decision is what you don't build

为什么值得关注：提出一个尖锐问题——团队能列出今年发布了什么，却对"砍掉了什么"沉默。强调"不做什么"才是最重要的产品决策。

  • 原文：https://liamnugent.me/posts/what-you-dont-build/

3. Planning with agents

为什么值得关注：Maggie Appleton 探讨与 AI Agent 协作规划时，为何需要更丰富、更厚实的界面和更好的"边界对象"（boundary objects）。

  • 原文：https://maggieappleton.com/planning-agents

4. Opusfived

为什么值得关注：一个关于 AI Agent 的互动喜剧——"把一个按钮变蓝，其他什么都别改"，讽刺 AI 助手永远无法"就只做那件事"。以幽默方式揭示当前 Agent 交互设计的痛点。

  • 原文：https://opusfived.dev/

二、视觉设计与排版工艺

这一类关注视觉细节、排版对齐和渐变等具体设计技艺。

5. Optical vs. mathematical alignment

为什么值得关注：探讨软件可以用数学精度放置对象，但人眼并不总是同意计算结果。对字体排版和 UI 对齐实践有直接指导意义。

  • 原文：https://pangrampangram.com/blogs/journal/optical-vs-mathematical-alignment

6. Let's talk about gradients

为什么值得关注：一篇关于渐变工具的短文，附带可操作的展示示例。对视觉设计师有实用参考价值。

  • 原文：https://brainfunctioncollapse.com/projects/gradients

7. Rauno's field notes: 5

为什么值得关注：Rauno（知名设计师）的现场笔记，讲述如何用交互式卡片堆叠替代分页箭头，解决紧凑 UI 空间约束问题。实战经验分享。

  • 原文：https://rauno.me/notes/5

三、无障碍与设计工具

这一类聚焦可访问性标准和设计师日常使用的工具。

8. WCAG Accessibility Guidelines Explorer

为什么值得关注：通过交互式演示展示无障碍违规与解决方案的对比，是学习和理解 WCAG 标准的实用工具。

  • 原文：https://emesstyle.com/a11y-design/

9. Bencho

为什么值得关注：一个交互式 UI 组件库，可以探索、调整并直接引入项目。对需要快速搭建界面的设计师和开发者很实用。

  • 原文：https://bencho.dev/

10. Sidebranch: worktree visual diffing

为什么值得关注：在运行中的应用内直接审查 PR——通过页面内小组件切换分支并并排比较 worktree。将代码审查与设计预览结合的创新工具。

  • 原文：https://sidebranch.dev/

四、AI 行业辩论与代码质量

这一类涉及 AI 发展节奏、开源政策辩论以及代码质量衡量等争议性话题。

11. We must pace the frontier

为什么值得关注：Dario Amodei 提出三步框架，主张 AI 公司应放缓能力进展以确保安全系统跟上。这是 AI 安全领域的重要政策提案。

  • 原文：https://darioamodei.com/post/we-must-pace-the-frontier

12. Dario, please

为什么值得关注：对上述 AI 末日论调的驳斥，认为 CEO 呼吁禁止开源实为保护企业护城河的自利策略。与第 11 篇形成鲜明对立，值得对照阅读。

  • 原文：https://pop.rdi.sh/dario-please/

13. Maybe we shouldn't be reviewing all this code

为什么值得关注：Martin Fowler 网站上的文章，质疑问题或许不是 AI 破坏了代码审查，而是我们一直用代码审查解决错误的问题。

  • 原文：https://martinfowler.com/rachels-ramblings/code-review.html

14. If coding is solved, what now?

为什么值得关注：探讨如何衡量代码"邋遢度"，为什么正确的代码仍可能侵蚀代码库，以及为什么人类直觉和品味仍然重要。

  • 原文：https://earendil.com/posts/measuring-code-sloppiness/

15. Seats and sunsets

为什么值得关注：Yegge 的文章，深入分析 Agent 编排经济学、模型能力阈值、token 消耗速率和结构性失败模式。对理解 AI Agent 商业逻辑有深度洞察。

  • 原文：https://yegge.ai/essays/seats-and-sunsets/
