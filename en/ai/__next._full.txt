It is a decoupled gateway, so everything is a plugin, including different providers, protocols (MCP, voice), modalities (images, videos), and gateway features (fallbacks, PII redaction, smart routing).<p>Instead of packaging tons of providers and features into one gateway, Respan provides a small core and public interfaces that teams can use to assemble the AI infrastructure their application needs. That way, users can build their own features as additional plugins without having to change the gateway&#x27;s core.<p>Here’s a video demo: <a href="https:&#x2F;&#x2F;www.youtube.com&#x2F;watch?v=pVv2ibXiTXM" rel="nofollow">https:&#x2F;&#x2F;www.youtube.com&#x2F;watch?v=pVv2ibXiTXM</a><p>There are countless LLM gateways and most of them solve a common problem: calling different providers from a single endpoint. However, adding new features can become prohibitively difficult. So developers can end up building another gateway to solve a specific problem.<p>We&#x27;ve been building our gateway based on LiteLLM since 2024, and now it&#x27;s providing services for thousands of orgs. Each org needs different API key settings, routes, and limits. To support that, we kept wrapping LiteLLM, adding more features to it, and at one stage, our wrapper code exceeded 100,000 lines.<p>This January, a routine LiteLLM upgrade caused intermittent connection errors, and we had to roll back. We still haven&#x27;t figured out the cause, but since then, we no longer upgrade LiteLLM directly and instead manually backport upstream fixes. These experiences made us realize that continuing to patch LiteLLM is not a sustainable long-term solution, and we had to redesign the gateway ourselves.<p>While redesigning our gateway, we wanted to make it easier to add features without breaking existing ones. Inspired by Nginx, we think an AI gateway should have a really small core, only responsible for dispatching events.<p>We believe that everything should be a plugin in our gateway, including providers (OpenAI, Anthropic, Gemini), protocols (chat, realtime voice, MCP), modalities (images, videos), and gateway features for reliability and security (smart routing, fallbacks, and PII redaction through example plugins). Beyond that, we want developers to be able to easily extend the gateway&#x27;s capabilities by adding their own plugins, without touching the core. Adding a provider, even your own, is dead simple, because quirks are plugins too and there’s nothing magical about them. A provider is a short file, Mistral’s is 22 lines, and each quirk, like Groq putting token usage in its own field, gets its own test.<p>Respan Gateway does more than let you call Claude or Gemini models from the OpenAI SDK. It handles tools, images, and reasoning protocols automatically: an application based on the OpenAI Realtime API can also use Gemini Live through the gateway, though not every feature translates. A simple chat app can use MCP tools configured in the gateway, without implementing MCP itself.<p>We also parse requests into a shared structure. When the client and provider use the same API, we preserve provider-specific fields in their native format, even if our shared structure doesn&#x27;t have a field for them. That way, the gateway can write them back instead of dropping them.<p>Here’s how it works:<p>An adapter hands each HTTP or WebSocket connection to the first client format that recognizes it. The format exposes the request as a two-way stream of typed input and output events. The core runs plugins in registration order, allowing them to choose a provider, filter or wrap either stream, make additional calls, return a response, or refuse the request. A provider format then opens the upstream connection.<p>If the client and provider use the same format and no plugin changes the payload, the original bytes and protocol-specific fields can pass through unchanged. When formats differ, they translate through shared types for messages, tool calls, results, streams, and usage. This stream model can represent both one-shot HTTP requests and long-lived bidirectional sessions.<p>The gateway is open source at <a href="https:&#x2F;&#x2F;github.com&#x2F;respanai&#x2F;respan-gateway" rel="nofollow">https:&#x2F;&#x2F;github.com&#x2F;respanai&#x2F;respan-gateway</a> under the MIT or Apache-2.0 license. You don&#x27;t need to use Respan&#x27;s hosted platform and can run it directly on your local machine. Build it from source, add your provider keys, and swap the base URL in a supported client. You can keep using the API your client already speaks. It&#x27;s still pre-alpha.<p>We make money from our hosted platform (<a href="https:&#x2F;&#x2F;www.respan.ai&#x2F;pricing">https:&#x2F;&#x2F;www.respan.ai&#x2F;pricing</a>), which runs the gateway for you with native observability and evals, along with unified billing.<p>If you’re building routing, tools, filtering, observability, or security for agents, we&#x27;d love to see it as a plugin.
