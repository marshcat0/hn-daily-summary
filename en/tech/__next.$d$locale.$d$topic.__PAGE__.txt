This gives you broad hardware compatibility with the same performance ceiling as hardware-specific kernels.<p>- Focus on best architectures: We write our tunable, highly efficient kernels for the most popular open-weights families. This allows us to achieve and surpass the performance of hardware or model specialized engines, without forcing ourselves to over-generalize at the cost of performance.<p>- Dynamic memory allocation: Magnitude reserves only enough memory up front to hold model weights. 11:T730,<p>During the 2025 November C++ ISO meeting Edison Design Group <a href="https://herbsutter.com/2025/11/10/trip-report-november-2025-iso-c-standards-meeting-kona-usa/" rel="ugc">announced that they would be winding down and that they will open-source their front end</a>. This is the repo containing said front end along with some other components like C and C++ back ends. There is also a <a href="https://edgcpp.org/" rel="ugc">website</a> with more info about the transition and a <a href="https://edgcpp.org/doc/" rel="ugc">documentation website</a>.</p>
<p>At least as far as my knowledge extends this is one of the four still extant C++ front ends (Clang, GCC, and MSVC being the others). It's most notably used as the front end for Visual Studio's Intellisense, and Intel's compiler used to use it before they switched to Clang.</p>
<p>Another interesting historical tidbit is that they were the only front end to implement C++98's <code>export template</code> feature, and their experience was  <a href="https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2003/n1426.pdf" rel="ugc">used to argue for the removal of the feature in C++11</a>, though according to <a href="https://stackoverflow.com/questions/5416872/using-export-keyword-with-templates#comment6130296_5416981" rel="ugc">this Stack Overflow comment</a> that specific paper didn't pass voting. The feature was eventually removed in C++11, but I'm unable to find exactly when and/or which paper did so. There's a <a href="https://herbsutter.com/2009/10/23/deprecating-export-considered-for-iso-c0x/" rel="ugc">2009 blog post by Herb Sutter</a> indicating support for removal/deprecation with deprecation getting the most support, so I guess the paper/vote happened sometime after that.</p>
